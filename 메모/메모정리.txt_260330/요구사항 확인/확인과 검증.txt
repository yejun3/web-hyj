요구사항 문서 검증 시 확인항목
1. 이해 가능성 : 읽는 사람이 같은 의미로 이해할 수 있는가
2. 일관성: 내용끼리 서로 충돌하지는 않는가
3. 완정성 : 필요한 내용이 빠지지 않았는가
4. 표준 준수: 회사 규칙을 따르는가?						
	
개발자 a -> 로그인 기능
개발자 b -> 회원로그인기능
개발자 c -> user login
개발자 d -> 로그인 모듈

위와 같이 작성했을떄 문제점
- 같은 기능인지 구별하기 어렵다
- 문서를 찾기 어렵다
- 유지보수가 어려워지다
- 협업효율이 감소한다.

요구사항 확인 기법
작성된 요구사항이 올바른지, 빠진 것은 없는지, 고객이 원하는 내용이 맞는지 확인하는 방법

1. 요구사항 검토 
- 여러 사람이 모여서 요구사항을 읽고 문제를 찾는다.
오타, 잘못된 가정, 애매한 표현, 누락, 모순, 표준위반점을 찾는다.
- 검토자 그룹을 어떻게 구성하는냐가 중요하다.
예를 들어 고객 중심 프로젝트에서는 검토자 그룹에 고객 대표자가 1명이상 포함되어야 한다.
- 검토는 시스템 정의서, 시스템 사양서, 소프트웨어 요구사항 명세서를 완성한 시점에서 이루어진다.

시스템 정의서 
- 무엇을 만드는지 큰 방향을 정의하는 문서 

시스템 사양서 
- 정의서 보다 조금 더 구체적인 문서( 그 기능들이 어떻게 동작할 것인지)

소프트 웨어 요구사항 명세서
- 개발자가 실제 구현할 수 있을 정도로 상세하게 적은 문서

2. 프로토 타이핑(Prototyping)
- 최종 제품을 만들기 전에 일부 기능이나 화면을 미리 만들어  사용자가 확인하도록 하는 방법
- 소프트웨어 요구사항에 대해 소프트웨어 엔지니어가 해석한 것을 확인할 수 있다.
- 처음에는 생각하지 못했던 새로운 요구사항을 도출할 수 있다.

장점 
- 분석가의 가정을 파악하고 잘못된 경우 유용한 피드백을 제공한다.
- 사용자 인터페이스의 동적인 행위가 문서나 그래픽 모델보다 프로토타입으로 이해하기 쉽다.
- 요구사항의 가변성이 프로토타이핑 이후에 급격히 감소한다.
- 잘못된 요구사항에 대해 자원낭비 방지

단점
- 핵심 기능보다 디자인에 집중하게 될 수 있다.
- 프로토 타입을 만드는 시간과 비용이 추가로 발생할 수 있다.

프로토타이핑 종류
종이에 그림: 가장 단순함

화면 프로토타입
- Figma와 같은 도구 사용

기능 프로토타입
- 일부 기능을 실제로 구현

모델 검증
- 분석 단계에서 만든 설계 그림이나 문서가 논리적으로 맞는지 확인하는 작업
- 개발 전에 만든 분석 모델이 올바르게 작성되었는지 확인하는 방법
- 개발 전에 모델 오류를 찾기 위해서 검증을 해야된다.
- 예를 들어 객체 모델의 경우 객체들 사이에 존재하는 의사소통 경로를 검증하기 위해 
    정적 분석을 수행하는 것이 유용하다.

모델 : 실제 시스템을 단순하게 그림으로 표현한 것을 의미한다.
          실제 프로그램 코드가 아니라 개발 전에 만드는 분석용 설계자료

모델의 종류
업무 흐름도: 사용자가 어떤 순서로 업무를 처리하는지 나타내는 그림
유스케이스 다이어그램: 사용자가 시스템으로 무엇을 할 수 있는지 나타낸 그림
객체 모델: 시스템 안에 어떤 객체들이 있고 서로 어떻게 연결되는지 나타낸 모델
클래스 다이어그램 : 클래스 속성, 메서드 관계를 표현한 그림
데이터 모델: 데이터베이스에 어떤 데이터가 저장되는지 나타난 모델

의사소통 경로 
= 객체들끼ㅣ리 정보를 주고받을 수 있는 연결 관계
예 : 도서 대여 시스템에서 회원이 도서를 빌리려면 다음과 같이 동작해야 한다.
회원 -> 대여 -> 도서

회원이 대여를 요청하고, 대여 객체는 도서 객체에게 재고나 대여 가능 여부를 확인해야 한다.
회원 -> 대여    도서
이렇게 되어 있으면 대여 객체가 도서 정보를 확인할 길이 없다.
필요한 의사소통 경로가 빠진 상태라고 한다.

정적 분석
- 프로그램을 직접 실행하는 것이 아닌 구조만 보고 검사하는 방식
- 객체 모델을 실행할 수 없지만 그림이나 관계를 보고 구조적으로 검사하는 것 

인수테스트
개발이 거의 끝난 후 만든 프로그램이 고객이 요구한 내용을 정말 만족하는지 최종 확인하는 테스트
- 요구사항의 중요한 속성은 최종제품이 요구사항을 만족시키는 기능인지 확인이 가능해야 한다.
- 각각의 요구사항을 어떻게 확인할 것인지에 대한 계획을 세워야한다.

회원은 로그인 할 수 있어야 한다.

2. 비밀번호 입력
3. 로그인 버튼 클릭
4. 메인 페이지 이동 여부 확인
