## 실무 시나리오

A 온라인 쇼핑몰은 회원과 주문 데이터를 관리하는 시스템을 운영하고 있다.

현재 개발팀은 주문 조회 성능 저하 문제를 해결하기 위해 물리 데이터 모델을 개선하려고 한다.

다음과 같은 요구사항이 존재한다.

- 회원은 여러 개의 주문을 생성할 수 있다.
- 존재하지 않는 회원의 주문 데이터는 저장되면 안 된다.
- 회원 이메일은 중복되면 안 된다.
- 회원 이름은 반드시 입력해야 한다.
- 특정 회원의 주문 내역 조회가 자주 발생한다.
- 다음 조회가 하루 수천 번 이상 실행된다.

# 문제

위 요구사항을 만족하도록 물리 데이터 모델을 설계하려고 한다.

다음 조건에 맞게 SQL을 작성하시오.

# 조건

- DBMS는 MySQL을 사용한다.
- PK 컬럼명은 테이블명_id 형식을 사용한다.
- 회원 테이블명은 `members` 이다.
- 주문 테이블명은 `orders` 이다.
- 회원 테이블 컬럼은 다음과 같다.

| 컬럼명 | 데이터 타입 |
| --- | --- |
| member_id | INT |
| member_name | VARCHAR(50) |
| email | VARCHAR(100) |
- 주문 테이블 컬럼은 다음과 같다.

| 컬럼명 | 데이터 타입 |
| --- | --- |
| order_id | INT |
| member_id | INT |
| order_date | DATE |
- 회원 테이블에는 PK, UNIQUE, NOT NULL 제약조건을 반드시 적용한다.
- 주문 테이블에는 FK 제약조건을 반드시 적용한다.
- 회원 번호 조회 성능 향상을 위한 단일 인덱스를 생성한다.
- 회원번호 + 주문일 조건 검색 성능 향상을 위한 복합 인덱스를 생성한다.
- FK 이름은 `fk_orders_members` 로 작성한다.
- 단일 인덱스 이름은 `idx_orders_member_id` 로 작성한다.
- 복합 인덱스 이름은 `idx_orders_member_date` 로 작성한다.

# 작성해야 하는 내용

1. `members` 테이블 생성 SQL
2. `orders` 테이블 생성 SQL
3. 단일 인덱스 생성 SQL
4. 복합 인덱스 생성 SQL

create table members(
  member_id int primary key,
  member_name VARCHAR(50) not null,
  email  VARCHAR(100) unique
);


create table orders(
  order_id int priamry key ,
  member_id INT,
  order_date DATE,
 constraint fk_orders_members foreign key(member_id) references members(member_id)
);

create index idx_orders_member_id
on orders(member_id);

create index idx_orders_member_date
on orders(member_id, order_date);

A 모바일 주문 서비스는 주문 요약 정보를 여러 프로그램에서 공통으로 사용하고 있다.

현재 개발팀은 다음 문제를 해결하려고 한다.

- 주문 조회 SQL이 여러 화면에 반복 작성되고 있다.
- 일반 직원은 회원 이메일(email)을 조회할 수 없어야 한다.
- 조회 결과를 하나의 가상 객체 형태로 재사용하려고 한다.
- 해당 객체를 통해 데이터 수정은 발생하지 않아야 한다.

현재 시스템에는 다음 테이블이 존재한다.

## members 테이블

| 컬럼명 | 데이터 타입 |
| --- | --- |
| member_id | INT |
| member_name | VARCHAR(50) |
| email | VARCHAR(100) |

## orders 테이블

| 컬럼명 | 데이터 타입 |
| --- | --- |
| order_id | INT |
| member_id | INT |
| order_date | DATE |

회원과 주문은 회원번호 기준으로 연결되어 있다.

# 문제

위 요구사항을 만족하도록 주문 요약 정보를 제공하는 View를 생성하시오.

# 조건

- DBMS는 MySQL 기준으로 작성한다.
- View 이름은 `v_order_summary` 로 작성한다.
- 조회 컬럼은 다음만 포함한다.

컬럼명

---

order_id

---

member_name

---

order_date

---

- 회원과 주문 데이터를 함께 조회해야 한다.
- SQL은 실제 실행 가능한 형태로 작성한다.

create or replace view v_order_summary as
  select o.order_id, m.member_name, o.order_date
    from orders o
    inner join members m 
     on o.member_id = m.member_id
    with read only;
(with read only은 MySQL에서는 지원 안됨)
(CREATE OR REPLACE TABLE 문법은 MySQL에서 지원되지 않는다.)
