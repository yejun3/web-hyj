UI 프로토타입 제작, 검토하기

UI 요구사항을 바탕으로 구성 요소를 정의하고 흐름을 설계하여 프로토타입 제작하기

1. UI 구성요소를 정의하기 (구성요소 중 무엇이 필요한지)
- 사용자 요구사항 및 시나리오 분석 결과 확인
- 화면별 주요 기능 식별 (업무 및 서비스 기준)
- 구성요소 유형 분류 -> 각 기능을 구성하는 버튼,입력창 등
- 각 구성요소의 속성 및 역할 정의
ㄴ 요소별 처리하는 정보 이벤트 등을 정리
2. UI 흐름을 설계한다.
- 주요 화면 목록 도출하기 
ㄴ (요구사항 명세서 확인, 유스케이스 기반으로 화면 도출, 벤치마킹)
화면 목록 정의
화면 ID     화면명    주요기능   비고
- 사용자 동선의 흐름 시나리오 작성하기 
ㄴ 사용자 페르소나 설정하기
ㄴ 시스템 사용목적 중심의 시나리오 작성하기
- 화면 동작 및 이동 조건 정의하기
ㄴ 각 화면의 실행 사전 조건이나 다음 화면으로 전환되는 조건정의, 사용자의 동작에 따른 화면의 동작 및 이동 흐름을 정의한다.
UI 흐름도 작성하기
- 도출된 화면과 사용자 흐름을 시각적으로 정리하여 전체 화면 흐름 구조를 한눈에 볼 수 있도록 UI 흐름도를 작성한다.
ㄴ 주요 화면과 화면 간 연결 흐름을 노드로 구성한다.
ㄴ 화면의 조건 분기/ 예외 흐름을 포함하여 작성
ㄴ 반복 가능성, 되돌아가기 흐름도를 고려하여 보완한다.
- 예외 흐름 및 오류 처리 흐름을 설계한다.
ㄴ 일반 흐름에서 벗어나는 예외 상황에 대한 UI 처리 기능을 정의하고, 메세지/알림 등을 제공하는 방법과 문구를 설계한다.

3. 기능중심의 간단한 UI 레이아웃 초안 만들기
- 기능 중심의 간단한  UI 레이아웃을 작성한다.
ㄴ 메인, 팝업과 같은 화면의 종류를 정의한다.
ㄴ 기능 흐름에 따른 화면 구성을 고안한다.
ㄴ 간단한 형태의 각 화면을 스케치한다.
- UI별 구성 요소 위치를 배치한다.
- 정보 구조 및 데이터 우선순위를 설정한다.
ㄴ 사용자가 정보를 효율적으로 이해할 수 있도록 중요한 정보와 기능을  어떤 순서로 보여줄지 정하고, 그에 맞는 정보 구조를 설계한다.
- 상호작용 과정 설명을 추가한다.
ㄴ 사용자는 시스템 사용 시 어떤 동작을 하는지 설명을 추가한다.
- 팀 내의 공유하고 의견 수렴하기
- 작성한 화면 초안을 팀원들과 공유하고 기능/디자인/사용성 관점에서 의견을 수렴하여 반영한다.

4. 시각젇으로 완성도 있고 동작 가능한 프로토타입 제작하기
- 색상, 폰트, 여백 등 시각 요소를 소프트웨어에 적용한다.
ㄴ UI에 적용할 색상, 폰트, 여백, 아이콘 스타일 등 디자인 요소의 기준을 수립한다.
ㄴ 버튼, 입력창, 목록 형태 등의 공통 UI 요소에 스타일 적용하기
ㄴ 디자인 도구를 활용하여 실제 화면에 스타일을 적용한다.
- 실제 서비스처럼 보이는, 동작하는 프로토타입 UI를 제작한다.
ㄴ HTML, CSS를 이용하여 기능의 일부만 동작하는 프로토타입
ㄴ 사용 흐름에 따라 기능 및 버튼 위치를 정의하여 구현한다.
ㄴ 로그인 실패 경고, 입력 정보 오류 등과 같은 상태를 구현한다.
- 화면 간 링크 연결 및 상호작용을 구현한다.
ㄴ 화면 간 이동 흐름을 설계하기 위해 버튼이나 메뉴를 클릭했을 때 연결될 다음 화면을 구체적으로 정의
ㄴ 사용자가 조작하였을 떄 어떤 반응이 일어나는지 추가한다.
ㄴ UI 설계 및 구현 도구를 활용해 실제로 동작하는 링크를 설정한다.
- 사용자와 개발 팀의 의견을 반영해 수정하고 반복 테스트를 수행한다.
ㄴ 사용성 테스트를 통해 디자인에 대한 의견 수집
 // 사용성 테스트 : 프로토타입의 사용
ㄴ 개선해야할 항목을 기능 중요도와 구현 난이도에 따라 분류
ㄴ 수집한 의견을 반영해 프로토타입을 수정한다.
- 최종 프로토타입을 확정하고 공유할 수 있는 링크와 파일을 준비한다.
ㄴ 모든 화면, 링크, 오류 메세지가 포함되어있는지 최종 디자인을 검토
ㄴ 외부 공유할 수 있는 링크 생성
ㄴ 프로토타입과 함께 기능 요약 문서와 화면 구성을 작성하여 개발팀에 전달

문제1. 화면 설계 과정 없이 요구사항 분석 후 바로 시스템 개발(코딩)에 착수했을 때, 프로젝트 후반부에 발생할 수 있는 수정 비용 및 시간적 측면의 부작용을 초기 프로토타입 목적과 연결하여 서술하시오.

: 만들어진 결과물이 사용자의 요구사항과 다를 수 있기 떄문에 나중에 수정비용 및 수정시간이 증가할 수 있다 따라서 프로토타입을 통해
  요구사항에 충족하고 있는지 미리 확인과 검증이 필요하다.

문제2. UI 구성 요소를 설계할 때, '저장' 버튼과 '취소' 버튼의 화면 내 배치 및 간격 규칙을 일관성(Consistency) 측면에서 어떻게 적용해야 하는지 그 설계 원칙을 서술하시오.

: ISO 9421-210 표준에 따라 사용자가 이해하기 쉽게 일관성이 유지되어야 한다.

문제3. 본문 교재에서는 나쁜 오류 메시지의 예시로 'Error 500'을 제시했습니다. 사용성 측면에서 이를 지양해야 하는 이유를 좋은 오류 메시지가 갖춰야 할 3가지 요소(문제 상황, 해결 행동, 표현 방식)와 비교하여 서술하시오.

: 사용자가 문제상황을 인식하고 해결할 방향으로 행동할 수 있도록 오류 원인과 오류가 발생한 부분을 표시해주어야 한다.

문제4. UI 구성 요소를 기능 기준으로 분류할 때, '아이디 입력창'이나 '비밀번호 입력창'과 같이 사용자로부터 데이터를 받아오는 역할을 하는 유형의 명칭을 쓰시오.

: 입력창

문제5. 사용자가 화면을 조작했을 때 시스템이 특정 동작을 발생시키도록 만드는 '사용자 행동(예: 버튼 클릭, 스와이프 등)'을 일컫는 UI 흐름 설계 용어를 쓰시오.

: 트리거

문제6. 시각 디자인 요소를 최소화하고 구조, 버튼 위치, 메뉴 배치, 화면 이동 흐름 중심의 설계에 집중하기 위해 초기 프로토타입 단계에서 빠르게 작성하는 화면 설계도의 명칭을 쓰시오.

: 와이어 프레임

문제: 웹 브라우저 기반으로 구동되며, 별도 설치 없이 실시간 공동 작업이 가능하여 현재 UI/UX 모사형 프로토타입 제작에 가장 널리 사용되는 도구의 명칭을 쓰시오.
