물리 데이터저장소 구성
관계형 데이터베이스 사이에서의 제약조건
PK - FK 연결되어 있는 두 개 테이블에 대한 제약조건

삭제했을 때 (ON DELETE..)
CASCAFE : PK값이 삭제되면 FK 쪽에서도 같이 삭제된다.
RESTRICT : FK쪽에서 사용중이면 PK의 값을 삭제할 수 없다.
NULLIFY : PK쪽 값이 삭제되면 FK 쪽에서는 NULL로 바뀐다.

수정했을 떄 (ON UPDATE..)
CASCAFE : PK값이 수정하면 FK 쪽에서도 같이 수정된다.
RESTRICT : FK쪽에서 사용중이면 PK의 값을 수정할 수 없다.
NULLIFY : PK쪽 값이 수정하면 FK 쪽에서는 NULL로 바뀐다.

언제 쓰냐?
테이블 만들 떄 외래키 제약조건 밑에 같이 속성을 작성해준다.

인덱스 설계 
- 조회 성능을 높이기 위해 어떤  컬럼에 인덱스를 적용시켜야 할까?

인덱스 컬럼의 분포도가 10~15% 이내가 일반적이다.
분포도의 값이 적을수록 인덱스 효율이 높다. -> 분포도가 넓다.

분포도 = (1/도메인의 수) x 100

조회 및 출력 조건으로 사용되는 컬럼인 경우
- WHERE에서 많이 사용되는 컬럼인가?

PK와 UNIQUE를 지정한 컬럼은 인덱스가 자동으로 만들어진다,

수정이 빈번하지 않은 컬럼을 선정을 한다.           

자주 조합되서 사용되는 컬럼은 결합 인덱스로 생성
                                                                                                                                                                                                                                                                                                                         
뷰(VIEW)
- SELECT를 한 결과를 저장하는 가상 테이블

뷰의 속성
REPLACE
- 뷰가 이미 존재하는 경우 기존 뷰를 새 내용으로 다시 생성하는  속성
CREATE OR REPLACE 뷰이름 AS
...

FORCE
- 기존 테이블이 존재하지 않아도 뷰를 생성하는 속성
- ORACLE에서 사용됨
- 단, 뷰를 사용하려고 하면 에러가 발생됨

NOFORCE 
- 기본 테이블이 존재할 떄만 뷰를 생성할 수 있게 함

WITH CHECK OPTION 
- 뷰의 조건을 만족하는 행만 INSERT 또는 UPDATE할 수 있도록 제한하는 속성

WITH READ ONLY
- 뷰를 읽기 전용으로 만드는 속성

뷰 설계시 고려사항
- 결국 view 안에 select문을 실행하는 것이기 떄문에 데이터가 너무 많으면 
   조회가 느릴 수 있다.
- 뷰 안에 조건이 있다면, 해당 조건 컬럼에 인덱스가 걸려있는지 확인

클러스터 
- 자주 같이 조회되는 데이터를 디스크의 가까운 위치에 저장해서 
   조회 속도를 높이는 물리적 저장 방법

분포도가 넓을 떄 유리하다.

여러 블록 이상의 테이블에 적용한다.
블록: DB가 데이터를 저장할 떄 블록이라는 저장 공간 단위로 저장한다.

- 데이터가 많은 경우 
디스크 내에서 수천 ~ 수만개 블록으로 나뉜다.
[블록1]
주문 데이터 일부

[블록2]
주문 데이터 일부

[블록3]
주문 데이터 일부

...
클러스터
관련 데이터를 가까운 블록에 모아서 저장

데이터가 많을 떄 클러스터를 사용한다.

디스크 이동이 감소 -> 읽는 블록 수 감소 -> 조회 속도가 높아진다.
검색은 빨라지지만 입력, 수정, 삭제는 느려질 수 있다.
UNION,DISTINCT, ORDER BY, GROUP BY가 번번한 컬럼이면 고려

파티션 설계
- 하나의 테이블 내에서 내부적으로 여러 조각으로 저장하는 기술
- 하나의 테이블만 사용되지만 DBMS는 데이터를 여러 저장구역으로 나누어 관리한다.

종류 
범위분할
- 기준이 사람이 설정
해시분할
- DB가 기준을 설정해서 데이터를 균등하게 분배
조합분할
- 서브 파티션을 생성한다.

디스크 설계 구성
- 데이터를 어디에 어떻게 저장할 것인지 계획하는 작업
                                                                                                                                            
정확한 용량을 산정하여 디스크 효율을 늘린다.

많은 작업이 발생하는 데이터를 한 곳에 몰아두지 않는다.

입출력 경합을 최소화하여 데이터의 접근 성능을 향상시킨다.
- 입출력 경합 : 여러 작업이 같은 디스크를 동시에 사용하는 상황

테이블 객체를 위한 테이블 스페이스와 인덱스 객체를 위한 테이블스페이스를 분리 구성한다.
- 실제 데이터와 인덱스를 따로 저장한다.
