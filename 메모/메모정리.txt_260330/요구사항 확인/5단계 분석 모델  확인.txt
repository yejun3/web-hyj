분석 모델  확인
제시한 분석모델이 개발할 응용소프트웨어에 미칠 영향을 검토하여 타당성 조사

분석모델 
정의
- 요구사항을 기능적으로 정리
- 개발하기 전에 시스템을 어떻게 이해했는지 정리한 그림과 설명

목적
- 분석모델이 실제 요구사항을 정확하게 반영하고 있는지를 확인
- 분석모델의 정확성, 완전성, 일관성 등을 점검

분석모델 검증 흐름의 이해
1단계 : 요구사항 작성
2단계 : 분석모델 작성
객체 모델 예시
유스케이스 모델
ERD
클래스 다이어그램
시퀀스 다이어그램
// 작성이유 : 문서로만 보면 이해가 어려움

3단계 : 검증 수행

분석모데
-요구사항을 기능적으로  정리하고 ,  시스템이 수행해야할 구조와 동작을 논리적으로 표현한 모델

유스케이스
2.     ERD
3.   시퀀스 다이어그램
4.   클래스 다이어그램

분석모델을 검증
실제 요구사항을 반영하고 있는지
개발을 위해 번영하고 있는지
개발을 위해 적절한지

검토 흐름
요구사항 작성
분석모델 작성
검증 수행
적합시 개발 진행

분석모델을 검토해야하는 이유
요구 사항이 충싫ㅏ게 반영되었는지(누락 OR 과한 해석 없는지)
오해나 불일치 방지
추가의견제시를 통한 보완
개발 가능성과 구체성 확보
프로젝트 리스크 사전 제거

검토관점
논리적으로 일관되어야 한다.
모순이 없어야 한다.
중복되는 내용이 없어야 한다.
충돌되는 내용이 없어야 한다.
구조적 불일치가 없어야한다.

검토관점
요구사항과 분석모델간 정합성
모델 내부 정합성
모델 간 정합성
비즈니스 논리와 정합성
