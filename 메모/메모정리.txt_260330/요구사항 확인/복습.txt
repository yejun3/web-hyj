4. 요구사항의 시스템화(개발) 타당성 분석
- 요구사항 문서를 만들었다고 바로 개발할 수 있는 것은 아니기 떄문
- 서버가 감당 가능한지, 현재기술로 가능한지, 비용이 얼마나 드는지, 유지보수가 가능한지
- 개발 전에 기술적으로 가능한지 검토하는 단계

기술적 타당성 검토의 흐름
1.성능 및 용량 산정 적정성 검토
-> 비기능 유형 중에서도 품질 속성에 대해서 체크
- 예상 사용량을 산정 
- 과거 유사 프로젝트의 사용량을 반영하고 필요하면 재조정
- 요구사항 중 성능이 비기능 요구사항을 만족하는지 판단
ㄴ 요구사항 미충족/충족 판단 -> 미충족시 재조정

2. 시스템 간  상호 운용성 검토
- 서로 다른 목적을 가진 시스템이 두 개 이상의 시스템이 정보를 주고받고 
- 서비스를 공유하면서  정상적으로 동작할 수 있는지 검토 

- 연동 대상 시스템이 무엇인지 확인
ㄴ 어떤 시스템과 연결해야 되는지 알아야 하기 때문에
ex) 결제 시스템, 택배 시스템, 보험시스템

- 서로 주고 받을 수 있는지 확인
 ㄴ 요청할 떄도 데이터를 줘야될 수도 있고
     응답받을 때도 데이터 를 받아야한다.
     -> 데이터 형식을 맞추어야 함
       ex) 나는 USER 외부시스템 MEMBER 라고 할 떄 MEMBER로 맞춰줘야 함

- 서비스 제공 방식이 맞는지 확인
 ㄴ 우리서비스: 사용자가 요청할 떄 실시간으로 제공
     외부시스템 : 하루에 1회만 제공
     판단 : 동작방식의 차이가 있다.
            - 추가적인 처리가 필요한지 판단
            - 외부시스템에서 받아와서 내 DB에 저장했다가 실시간으로 제공


- 최종적으로 연동가능 여부 판단
 ㄴ 요구사항을 실제 구현 가능한지 결정
ex) 요구사항 : 사용자가 주문하면 즉시 배송상태를 확인할 수 있어야한다.
     검토결과 : 택배 시스템은 하루에 1회만 정보제공
     판단 : 실시간 제공은 현실적으로 불가능
     결과 : 요구사항 수정 필요
      -> 수정예시:  요구사항 수정
                          ㄴ 사용자는 배송사태 정보를 하루 1회 갱신된 기준으로 확인할 수 있다.
 
3. IT 시장 성숙도 및 트렌드 부합성 검토
시장 성숙도 
- 사용하려는 기술이나 제품이 시장에서 충분히 검증되었는가
  ㄴ 확인 항목
        1. 사용하는 기업 수
        2. 사용하는 기술자
        3. 기술 지원 여부
        4. 시장 점유율
  사용할 기술 확인 
   -> 어떤 기술을 사용할 예정인지 알아야함
  시장성숙도 확인
   -> 현재 안정적으로 사용되는 기술인지 확인
  기술발전 방향 확인
   -> 앞으로도 사용될 기술인지 판단
  요구사항 적합 여부 판단 
   -> 향후 유지보수가 가능한지 판단하기 위해

4. 기술적 위험 분석 검토

  문제가 생겼을 때 영향이 얼마나 큰지를 판단하는 과정
