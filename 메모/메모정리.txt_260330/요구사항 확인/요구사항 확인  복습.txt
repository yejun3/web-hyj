선정 시 고려사항
1.신뢰도
- 장기간 시스템을 운영할 떄 고장이 잘 안나는가
- 특정 프로그램의 메모리 누수로 인한 성능 저하가 없는가
    ㄴ 프로그램을 실행하고 점유한  메모리가 프로그램 종료 후에도 반납되지 않음
- 운영체제상 보안상 허점으로 반복적인 패치 설치를 위한 재기동( 안 일어난느게 좋음)
- 운영체제의 버그 등으로 인한 패치 설치를 위한 재기동
2. 성능
- 대규모 동시 처리를 안정적으로  할 수 있는가
- 대규모 파일 작업처리가 가능한가
- 지원 가능한 메모리크기(32bit,64bit)
3. 기술지원
- 공급벤더들의 안정적인 기술지원(문제 생길 시 도움을 잘 주는가)
- 다수의 사용자들간의 정보공유
- 오픈소스 여부(가격이 저렴)
4.주변기기
- 설치 가능한 하드웨어
- 다수의 주변기기 지원여부(프린터, 스캐너, usb, 그래픽카드)
5.구축비용
- 지원 가능한 하드웨어 비용(cpu 요구사항, 메모리 요구사항, 저장장치 요구사항)
- 설치할 응용 프로그램의 라이센스 정책 및 비용(운영체제 위에 설치할 프로그램 등의 비용)
- 유지 및 관리비용(시스템을 구축한뒤 운영하기 위한 필요비용)
ㄴ  서버 전기세(서버를 계속 켜두는 비용)
ㄴ 클라우드 사용료(AWS 이용 비용)
ㄴ 유지보수 인력 비용(관리자 급여)
ㄴ 데이터 백업 저장 비용
6, 총 소유 비용(TCO)
- 시스템을 사용하는 전체 기간동안 발생하는 모든 비용

// 라이선스 종류

* GPL(제네럴 퍼블릭 라이센스)
- 오픈소스이지만 원본프로그램을 수정시  수정한 코드를 공개해야함

* GNU AGPL v3.0
- GPL보다 강력한 라이센스 
- 웹 서비스처럼 서버레서 실행되고 사용자가 인터넷으로 접속하는 
    경우에도 소스코드 공개 의무가 생길 수있다.

* BSD 
- 상업적으로 상용할 수도 있고, 수정해서 판매할 수도 있으며 소스코드를 공개하지 않아도 된다,
- 대신 저작권 표시와 라이선스 문구는 유지해야 한다.
  
* LGPL (Lesser GPL)
- GPL보다 제한이 약하다.
- 기업들이 많이 사용한다.
- 라이브러리 자체 수정 → 공개 필요
- 라이브러리를 사용하는 내 프로그램 → 공개 안 해도 됨

*CDDL (Common Development and Distribution License)
- GPL보다 훨씬 유연하다.
- GlassFish가 사용한다.
- 수정 가능
- 수정한 파일만 공개
- 상업적 사용 가능, 기업 친화적
- GPL과 혼합 시 충돌 가능성이 있는 단점이 있음

*Apache 2.0
- Jetty에서 사용하는 매우 자유로운 라이선스다.
- 실무에서 굉장히 많이 사용한다.
- 무료 사용 가능 
- 수정 가능
- 소스 공개 의무 없음
- 상업적 사용 가능, 특허권 보호 포함
- 매우 자유롭고 기업 선호도가 높음
GPL은 전체 공개를 요구하지만 CDDL은 일부만 공개한다.

*EPL (Eclipse Public License)
- Eclipse 재단에서 만든 라이선스다.
- Jetty가 사용한다.
- 수정 가능
- 수정한 부분만 공개
- 상업적 사용 가능

// 안정적인 트랜잭션 처리
- 트랜잭션(Transaction)은 **여러 작업을 하나의 작업 단위로 묶는 것**
- 쉽게 말하면  전부 성공하거나, 하나라도 실패하면 전부 취소되는 작업 묶음”이다.

- WAS에서 트랜잭션 처리가 중요한 이유
:  WAS는 사용자의 요청을 받아 비즈니스 로직을 실행한다.
  이 과정에서 DB 작업이 여러 번 발생할 수 있다.

- 안정적인 트랜잭션 처리에서 확인할 내용
확인 항목	                   설명
Commit 지원	           모든 작업이 성공했을 때 확정 저장
Rollback 지원	          중간에 실패하면 전체 취소
동시성 제어	          여러 사용자가 동시에 접근해도 데이터 충돌 방지
장애 발생 시 복구	  처리 중 장애가 나도 데이터 일관성 유지
분산 트랜잭션 지원	  여러 DB나 시스템을 함께 처리할 수 있는지

//패치 재기동 관련 확인해야 하는 내용
확인 항목	                      설명
패치 주기	                      패치가 너무 자주 필요한지
패치 안정성	              패치 후 장애 발생 가능성이 낮은지
무중단 패치 가능 여부	      서비스 중단 없이 적용 가능한지
재기동 시간	              재시작에 얼마나 걸리는지
롤백 가능 여부	              패치 실패 시 이전 상태로 되돌릴 수 있는지

2. 성능(Performance)
- WAS가 사용자 요청을 얼마나 빠르고 효율적으로 처리할 수 있는가
- 대규모 트랜잭션 요청 처리를 할 수 있는가
- 다양한 설정옵션을 지원
- GC(Garbage Collection) 옵션
    : 필요없는 메모리를 자동으로 정리하는 기능

3.기술지원
- 공급 벤더에서 안정적으로 기술지원을 제공하는지
- WAS 사용자들이 얼마나 많고, 정보를 공유하는지
- WAS 내부 소스코드가 공개되어있는지 여부

확인해야 하는 항목
확인 항목	                             설명
최대 동시 사용자 수	             몇 명까지 처리 가능한지
TPS (Transaction Per Second)     초당 처리 가능한 거래 수
응답 속도	                             요청 처리 시간
스레드 처리 수	                     동시에 실행 가능한 작업 수
부하 테스트 결과	                     많은 요청 시 성능

오픈소스
- 소스코드가 공개되어있고, 자유롭게 사용가능한 프로그램 
- 아무제한 없이 사용되는 것은 아니고 라이선스 규칙을 따라야한다.
장점
비용절감: 무료로 사용가능
자유로운 수정 : 기능 추가 가능
커뮤니티 활성화 : 자료가 풍부하다.
빠른 업데이트 :  개발자의 참여가 많다.

단점
공식 지원 부족: 제조사의 지원이 약할 수 있음
설정 난이도 : 직접 설정 필요
라이선스 확인 필요 : GPL 등 확인 필요

4. 구축비용
- 라이선스 비용(상용WAS는 기능과 기술자원을 제공하는 대신 비용을 받는다.)
- 유지 관리 비용(서버 룬영 비용, 유지 보수비용, 보안 패치 적용, 장애 대을 비용, 백업 비용)
- TCO(처음부터 끝까지 총 소유 비용) 초기 구매비용 +유지보수 비용
