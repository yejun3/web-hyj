2. 개발 기술 환경 정의
개발 기술 환경
구분	설명

1-1. 운영체제(OS, Operating System) 
- 컴퓨터와 프로그램 사이에서 중간 관리자 역할을 하는 기본 소프트웨어
컴퓨터의 하드웨어와 소프트웨어 자원을 관리하고, 
프로그램이 실행될 수 있도록 공통 서비스를 제공하는 소프트웨어를 의미

1-2. 운영체제의 종류 및 특징 
종류	                        저작자                                   주요 용도
Windows	                Microsoft                               중소 규모 서버, 개인용 PC, 태블릿 PC, 임베디드 시스템
UNIX	IBM(AIX),           HP(HP-UX), SUN(Solaris)           대용량 처리, 안정성이 요구되는 서버, NAS, 워크스테이션
Linux                   	Linus Torvalds                         중대 규모 서버
iOS	                        Apple                                     스마트폰, 태블릿 PC, 음악 플레이어
Android             	Google                                   스마트폰, 태블릿 PC


1-3. 운영체제 선정 시 고려 사항

1. 신뢰도 

- 장기간 운영시 장애 발생  가능성
:  서버는 몇달 몇 년 동안 계속 켜져있어야 함
   운영체제 자체의 문제로 인해 시스템이 멈추거나 느려지거나 재부팅이 필요할 수 있다.

-메모리 누수
: 프로그램이 사용한 메모리를 다시 반납하지 않는 문제이다.
 , 메모리 누수 발생 시 서버가 느려지므로 확인 필요

- 보안 취약점

- 버그

2. 성능
- 대규모 동시 사용자 요청 처리
: 요청(Request) -> 사용자가 서버에 보내는 작업 요청입니다.
 , 많은 사용자가 동시에 시스템에 접속했을때 안정적으로 처리할 수 있어야 함

- 대규모 및 대량 파일 작업 처리
: 용량이 큰 파일을 안정적으로 요청처리가 가능한지 확인

// 문제 유형
-- 어떤 서버에서 장애가 발생했을 떄 운영체제의 어떤 항목이 문제인지 파악하는 문제

- 지원 가능한 메모리 크기(32bit, 64bit)
: 운영체제가 얼마나 많은 메모리(RAM)를 사용할 수 있는지를 의미한다.
  메모리는 프로그램이 실행될 때 사용하는 작업 공간
  ㄴ 대규모 시스템에서는 메모리가 부족해질 수 있습니다.

// 32bit 운영체제는 최대 약 4GB 메모리까지만 접근 가능
// 64bit 운영체제는 4GB 이상의 메모리를 사용가능

// 캐시(Cache)
- 자주 사용하는 데이터나 값을 미리 복사해놓는 임시 장소를 가리킨다
- 저장공간이 작고 비용이 비싼 대신에 빠른 성능을 제공한다.
- 캐시데이터만을 모으는 메모리 -> 발열이 심하고 비용이 너무 비싸서 현실성이 없다.

3.기술 지원
- 공급 벤더들의 안정적인 기술 지원
: 운영체제에서 문제가 생길 시 공급업체나 만든 회사에서 안정적으로 도움을 주는지 고려
- 다수의 사용자와 정보공유
: 운영체제를 사용하는 사람들이 많으면 그 만큼 문제해결방법과 사례를 얻기 쉬워진다.
- 오픈 소스 여부(Linux)
: Linux가 왜 많이 사용이유: 비용 적음, 자유로운 수정 가능, 서버환경에 최적화

4.주변 기기
- 설치 가능한 하드웨어
: 운영체제는 CPU 구조, 메인보드, 저장장치 방식 등에 따라 설치 가능 여부가 달라짐

//주변 기기란?
- 컴퓨터 본체 외부에 연결되는 장치이다.
주변 기기	                역할
프린터	                문서 출력
스캐너	                문서 이미지 입력
USB 메모리                 파일 저장
웹캠	                        영상 촬영
마우스 / 키보드	        입력 장치
그래픽카드	                 화면 출력 및 GPU 연산
사운드 카드	         음성 출력
네트워크 장치	         인터넷 연결

- 드라이버
: 운영체제가 주변 기기와 대화하기 위한 프로그램이다.
    운영체제 ↔ 드라이버 ↔ 주변 기기
     드라이버가 없으면 운영체제가 장치를 이해할 수 없습니다.

5.구축 비용
- 운영체제재를 쓰기위한 컴퓨터나 서버장비 비용
: 하드웨어 비용, 서버비용, 라이센스 비용, 유지관리 비용, 총 소유 비용(TCO)

//TCO(Total Cost of Ownership)
:  시스템을 사용하는 전체 기간 동안 발생하는 모든 비용

1-4. DBMS 주요 특징 및 고려사항

DBMS의 종류 및 특징
- DBMS(Database Management System)
   : 데이터를 저장하고 관리하는 프로그램 

DBMS의 주요 기능
: 데이터 저장, 조회, 수정, 삭제, 보안관리(권한 권리) ,백업및 복구, 동시처리

1. Oracle
- Oracle DB: 세계적으로 많이 사용되는 대표적인 상용 데이터베이스
Oracle의 특징 
:  안정성이 높고 백업 복구 및 클러스터 기능 지원 등 기업기능 풍부
    비용이 비싸고 관리가 어려움

//클러스터(Claster)
: 여러대의 독립된 컴퓨터나 서버 혹은 데이터들을 하나로 묶어 '단일시스템'처럼 작동하게 만드는 기능 및 기술

IBM DB2
- IBM에서 만든 기업용 DBMS입니다.
- Oracle처럼 대규모 시스템에서 사용됩니다.

3. Microsoft SQL Server
- Microsoft에서 만든 상용 DBMS
- Windows 서버, 중소기업, 사내 업무 시스템에서 많이 사용
- 학습난이도가 비교적 쉽고 초보자 접근이 쉬움
- 사용하기 쉽고 관리하기 편하고 Windows 환경과 잘 어울림 하지만 무료가 아님

SSMS(Sql Server Management Studio)
- Microsoft SQL Server를 관리하기 위한 전용 프로그램

Active Directory
-windows 계정과 사용자 권한을 중앙에서 관리하는 시스템

//.NET
-Microsoft의 개발 플랫폼
-C#이 포함된다.

4.MySQL
- 세계에서 가장 많이 사용되는 오픈 소스 관계형 데이터베이스(RDBMS) 중 하나
- 오픈소스(무료) 이기 때문에 개인이나 기업에서 많이 사용
- 배우기 쉽고 웹 개발에 많이 사용
- Linux , Apache. MySQL, PHP 조합이 유명하다 -> LAMP구조
- 고급튜닝이 불가능

//튜닝 
- 데이터 베이스가 더 빠르고 효율적으로 동작하도록 최저화하는 작업
- 조회속도 개선
- cpu 사용량을 감소
- 메모리 효율 증가
- 대량 동시접속 처리
- 디스크 I/O를 감소

실행계획 최적화 기능이 상대적으로 약함
DMBS는 SQL 실행전에 "어떤 방식으로 데이터를 찾는게 가장 빠를까?"를 계산
이걸 실행 계획이라고도 한다.
MySQL도 실행 계획이 있지만. Oracle과 같은 사용 DB보다 세밀함이 부족한 경우가 있다.

옵티마이저
-SQL 실행전략을 자동으로 결정하는 엔진
- 오라클에 비해서는 세밀하지 못하다.

대규모 병렬처리에 약함
MySQL은 전통적으로 단순 웹서비스 중심, 읽기 위주의 구조에 강점이 있다.
그래서 초대형 데이터 분석에는 한계가 있었다.

5. SQLite
매우 가볍고 작은 데이터베이스입니다.
- 주용도 : 스마트폰, 태블릿 PC 등의 임베디드(기계) 데이터베이스
- 설치부담적고 소규모 데이터처리에 강함

MongoDB
대표적인 NoSQL 데이터베이스 (Not Only SQL)
 ㄴ SQL에서만 쓰이는 데이터베이스가 아니다 ( 테이블 저장 방식이 아님)
  ㄴ JSON 형태, 유연한 구조로 데이터를 저장하는 방식 
       (json 형태가 데이터가 더 가볍기 떄문에 대용량 데이터가 저장 가능)
- join 기능은 약해서 관계형 데이터베이스 처리가 복잡
-----------------------------------------------------------------여기까지는 하드디스크에 저장
7. Redis
- 데이터를 메모리(RAM)에 저장하는 초고속 데이터베이스
속도 : 캐시 > 메모리 > 하드디스크

Redis : 데이터를 메모리에 저장함
실시간 메서지 기능
publish -> 메세지 보내기
subscribe -> 메세지 받기
                
   ㄴ 분할 테이블
- 대량 거래 처리 성능 (동시에 많은 작업 처리)
- 다양한 튜닝 옵션 지원
- 비용 기반 최적화 지원 및 설정 최소화
- 비용 기반 최적화(Cost Based Optimization)
   ㄴ 가장 적은 비용으로 실행 가능한 방법을 계산하는 기능입니다.
