1 현행 시스템의 분석
- 새 시스템을 만들거나 지금 시스템을 개선하기 위해 현재 사용중인 업무방식, 프로그램,
   데이터, 서버, 네트워크, 문제점을 조사하고 정리하는 활동

목적
- 새로운 시스탬을 만들 때 정확하게 만들기 위해서 현재 상황을 이해한다.

문제점 
1. 기존 업무의 흐름을 모른다면 필요한 기능을 빠뜨릴 수 있다.
2. 기존 데이터 구조를 모른다면 데이터 이전 시 오류가 발생
3.  기존 시스템 연동을 모른다면 외부 시스템과의 연결 실패가 될 수있다.
4. 사용자 불편사항을 모른다면 시스템을 만들어도 만족도가 낮다.
5. 현재 오류 원인을 모른다면 문제해결이 아닌 단순 재개발이 된다.

현행 시스템 파악 절차 

1단계 : 현행 시스템의 구성, 기능, 인터페이스 현황 파악
- 현재 시스템이 무엇으로 구성되고 있고, 어떤 기능을 제공하고, 
   다른 시스템과 어떻게 연결되어 있는지 파악

시스템 구성현황 파악
- 현재 운영중인 시스템의 종류와 역할을 정리하는 것 
- 각 시스템이 어떤 업무를 담당하는지까지 정리한다.

기능 현황 파악 
- 각 시스템이 제공하는 기능을 정리하는 것 

수강생 관리 시스템 
수강생 등록 : 신규 수강생을 등록
수강생 조회 : 학원에 다니는 수강생을 조회
수강생 수정 : 학원에 다니는 수강생 정보 수정
수강생 삭제 : 잘못 등록된 수강생 정보를 삭제

인터페이스: 시스템과 시스템간에 어떻게 상호작용할지 미리 약속된 것
인터페이스 현황 파악 
- 시스템과 시스템이 데이터를 주고받는 연결 지점을 의미
ㄴ ex 쇼핑몰)
결제 api -> 주문번호, 결제금액, 결제 상태
택배사 api -> 주문번호, 주소, 송장번호
문자발송 api -> 전화번호, 메세지 내용 
이메일 api -> 이메일 주소, 인증 코드
copang.com/search?q=데이터
(사용자 입장에서는 화면을 클릭한것 뿐이지만 실제는 위에 데이터를 넘긴것이다.)

API(Application Programming Interface) : 응용 프로그램 인터페이스
- 서로 다른 프로그램끼리 상호작용 할때 사용되는  기능들의 약속
- 프로그램간의 소통을 위한 메뉴판 역할
- API 요청과 응답의 기본 구조
: 요청주소, 요청 방법, 요청 데이터, 응답데이터 

- 인터페이스 현황 확인 내용
: 연동 시스템명, 연동방식, 송신데이터, 수신데이터 , 연동 주기, 오류처리 방식

- 현재 시스템이 어떤 구조로 만들어져 있는지 조사하는 일

아키텍쳐 
- 시스템의 구성

아키텍쳐 예시)
-  2-Tier 구조(클라이언트- DB서버) : 
        : 초기프로그램에 쓰임 , 보안, 유지보수가 어려움
- 3-Tier 구조(프론트엔드- 백엔드 서버 - 데이터 베이스) 
        : 역할이 분리되어 유지보수 쉬움 (가장 기본적인 서비스 구조) 
- MVC 구조 (model- view - controller)
         : Controller	      요청을 받음
          Service	     핵심 로직 처리
          Repository        DB 접근
          Entity	     DB 테이블과 연결되는 객체
          DTO	     요청/응답 데이터 전달 객체
- 레이어드 아키텍처

소프트 구성 현황 파악 
- 현재 시스템이 어떤 소프트웨어를 사용하고 있는지 조사하는 일

1단계 산출물
- 시스템 현황 조사서
현재 시스템 구성과 운영 상태를 정리한 문서
- 소프트웨어 설치 현황표
 서버별 설치 소프트웨어 목록 정리
- 인프라 구성 현황도
현재 서버, 네트워크, DB 등의 연결 구조 정리
- 인터뷰 및 요구사항 정리서
운영 담당자 의견 및 문제점 정리

2단계 산출물 
- 시스템 아키텍쳐 구상도 
클라이언트부터 인프라까지 전체 구성을 한 눈에 파악할 수 있다.
- 소프트웨어 구성 목록
시스템을 구성하는 소프트웨어를 영역별로 정리한 목록
-소프트웨어 버전 현황표
현재 사용버전, 최신 버전, 업데이트 상태를 한눈에 파악할 수 있는 표
- 기술스택 정리표
역할표 기술 스택을 목적, 선택이유, 대안까지 함께 정리한 표

클라우드: 데이터와 프로그램을 내 컴퓨터나 스마트폰이 아닌 인터넷상의 서버에 저장하고 관리하는 기술

클라우드 환경
- 회사 안에 직접 서버를 설치하지 않고, 인터넷으로 필요한 컴퓨터 자원을 빌려 쓰는 방식
- 인터넷을 통해 서버, 저장공간, 데이터베이스 같은 IT 자원을 빌려서 사용하는 환경

온프레미스
- 회사의 서버와 시스템을 **회사 내부에 직접 설치해서 운영하는 방식**
- 은행이나 군사기지 등 외부에 데이터를 두기 어려운 곳, 보안 떄문에 사용

클라우드 <-> 온프레미스
서로 반대되는 개념 직접 관리하냐 외부에서 사용

→ DNS: 도메인 이름을 컴퓨터가 이해할 수 있는 IP 주소로 변환해주는 시스템
 (예: www.example.com)을 컴퓨터가 이해할 수 있는 숫자 형태의 IP 주소(예: 192.0.2.1)로 변환
-> 로드 밸런서 : 클라이언트와 서버 간의 트래픽을 효율적으로 분배시켜서 효율성을 높이는 역할


- AWS(아마존이 제공하는 클라우드 환경) 기준으로 다음과 같이 볼 수 있다.
    사용자
    → Route 53  ( DNS 역할)
    → CloudFront (로드밸런서 역할)
    → S3 또는 ALB
    → EC2
    → RDS

보안 및 접근 제어 파악
- 네트워크 분석에서는 보안 설정도 함께 확인해야 한다.

| 항목                                       | 확인 내용 |
| 방화벽                                    | 어떤 포트가 열려 있는지 |
| 보안 그룹                                | EC2, RDS 접근 제한 설정 |
| SSL 인증서                               | HTTPS 적용 여부 | 
| VPN                                        | 내부 시스템 접근 방식 |
| 접근 권한                                 | 관리자, 개발자, 외부 사용자 권한 |
| 포트                                        | 80, 443, 22, 3306(MySQL 접속포트) 등의 접근 가능 여부 |

포트(port) 
- 외부와 데이터를 주고받는 통로이자 접속지점
SSL(Secure Sockets Layer) 인증서
- 웹 사이트와 사용자 브라우저 간에 데이터를 암호화하여 개인정보 노출을 막는 디지털 보안 솔루션
-> https를 쓰고싶으면 ssl인증서 필요 

- 데이터 암호화

- 데이터 무결성
