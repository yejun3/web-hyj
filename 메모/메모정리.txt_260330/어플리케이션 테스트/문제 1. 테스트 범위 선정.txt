기능 현재 상황
A. 회원 프로필 사진 변경   최근 변경 없음, 장애 발생 시 영향 낮음
B. 카드 결제   외부 카드사 시스템과 연계되며 장애 발생 시 주문 불가
C. 상품 상세 조회   하루 평균 20만 회 사용
D. 공지사항 조회   최근 변경 없음, 사용 빈도 낮음
E. 주문 취소 및 환불   최근 프로그램이 수정되었으며 결제 시스템과 연계됨
F. 회사 소개 화면   정적 화면이며 업무 처리와 직접적인 관계 없음
요구사항

테스트 범위 선정 기준으로 다음 네 가지를 사용한다.

업무 중요도
장애 발생 시 영향
최근 변경 여부
외부 시스템 연계 또는 사용 빈도

위 조건을 적용하여 우선적으로 테스트해야 할 기능 3개를 선정하고, 각 기능을 선정한 이유를 주어진 선정 기준과 연결하여 서술하시오.
B,C,D
- 카드 결제: 장애가 발생하면 고객이 주문을 완료할 수 없으므로 업무 중요도와 장애 영향도가 높다.
- 상품상세 조회 : 하루 평균 20만회일 정도로 시스템 사용빈도가 높다.
- 주문 취소 및 환불 : 최근 프로그램 변경이 있었고 외부 결제 시스템과 연계되기 떄문에 시스템 연계 위험을 고려해야한다.

문제 3. 테스트 시나리오와 테스트 케이스 설계

쇼핑몰의 카드 결제 업무 흐름은 다음과 같다.

로그인
 → 상품 선택
 → 주문서 작성
 → 카드 결제
 → 주문 데이터 저장
 → 주문 완료 화면

카드 결제 과정에서 다음 요구사항을 반드시 만족해야 한다.

정상 카드이면 결제가 승인되어야 한다.
카드사에서 승인을 거절하면 주문이 완료되어서는 안 된다.
결제가 성공하면 주문 정보가 DB에 저장되어야 한다.
결제 버튼을 여러 번 클릭하더라도 동일한 주문이 중복 결제되어서는 안 된다.
요구사항

위 업무 전체를 하나의 테스트 시나리오로 보고, 요구사항을 검증하기 위한 테스트 케이스 4개를 작성하시오.

각 테스트 케이스에는 반드시 다음 내용을 포함한다.

테스트 조건 → 예상 결과
- 정상카드를 이용하여 결제를 요청한다. -> 카드결제가 승인되고 주문 완료 화면으로 이동해야한다.

- 카드사에서 승인을 거절하도록 설정된 카드로  결제를 요청한다. -> 결제가 실패하고 주문이 완료되어서는 안된다.

- 정상 카드로 결제를 완료한다. -> 결제 성공 후 해당 주문 정보가 DB에 정상적으로 저장되어야 한다.

- 결제 버튼을 연속으로 여러 번 클릭한다. -> 하나의 주문에 대한 결제가 한번만 처리되어야 하며 중복 주문 또는 중복 결제가 발생해서는 안된다.

문제 4. 테스트 데이터 관리

쇼핑몰 주문 기능을 테스트하기 위해 개발자가 실제 운영 DB를 그대로 사용하려고 한다.

테스트 과정에서는 다음 작업을 수행한다.

테스트 회원의 개인정보 조회
상품 주문
주문 취소
결제
고객 문자 발송

현재 운영 DB에는 실제 고객의 이름, 전화번호, 주소 및 실제 주문 데이터가 저장되어 있다.

요구사항

운영 DB를 그대로 사용하여 테스트할 경우 발생할 수 있는 문제를 3가지 작성하고, 이를 방지하기 위한 테스트 데이터 관리 방법을 1가지 작성하시오.
문제점 
- 테스트 과정에서 실제 데이터 고객 데이터가 변경되거나 삭제될 수 있다.
- 실제 고객의 이름, 전화번호, 주소 등의 개인정보가 테스트 담당자에게 노출될 수 있다.
- 테스트 주문이나 결제가 매출에 반영되거나 테스트 문자가 실제 고객에게 발송될 수 있다.

이를 방지하기 위해 실제 운영 데이터를 직접 사용하는 대신 별도의 운영 데이터를 테스트 환경으로 복사하고 개인정보를 마스킹하여 테스트데이터로 사용해야한다.

문제 5. 기능 단위별 테스트 분석

회원가입 기능은 다음과 같이 동작한다.

회원가입 화면
      ↓
사용자 정보 입력
      ↓
서버에서 입력값 검증
      ↓
외부 휴대전화 인증 시스템 호출
      ↓

가입 완료 화면 출력

B. 가입 완료 화면에는 정상적으로 표시되지만 DB의 전화번호가 잘못 저장된다.

데이터 입출력
- B는 데이터 입출력을 확인해야한다. DB에 실제 저장된 전화번호가 잘못되었기 때문이다.

인터페이스
- C는 인터페이스를 확인해야한다. 요청 데이터 형식이 잘못되었으므로 시스템 간 데이터 전달 및 변환 부분을 확인해야한다.

서버 모듈
- D는 서버 모듈을 확인해야한다. 나이를 계산하는 로직이 잘못됐으니까

문제 1. 결함 여부 판단 및 근거 작성

온라인 쇼핑몰의 회원가입 기능에 다음 요구사항이 정의되어 있다.

비밀번호는 8자 이상 입력해야 한다.
비밀번호가 8자 미만이면 "비밀번호는 8자 이상 입력해야 합니다."라는 메시지를 출력해야 한다.
회원가입 성공 시 입력한 회원정보를 DB에 저장해야 한다.

테스트 결과는 다음과 같다.

테스트 내용   실제 결과
비밀번호 7자 입력   회원가입이 정상 처리됨
비밀번호 5자 입력   아무 메시지 없이 회원가입 화면 유지
정상 회원가입   화면에서는 가입 완료가 표시되지만 DB에 저장되지 않음
요구사항

위 세 가지 테스트 결과에 대해 각각 다음 내용을 서술하시오.

결함 여부
- 결함 여부 있음
결함이라고 판단한 근거
- 요구사항에 비밀번호가 8자 이상이되야 입력이 가능한데 비밀번호가 8자 아래여도 회원가입이 정상처리 됨

테스트 일시: 2026년 8월 7일
테스트 담당자: 김테스터
테스트 화면: 주문 결제 화면
입력값: 상품 수량 2개, 결제금액 30,000원
수행 절차:
상품을 장바구니에 담는다.
주문 화면으로 이동한다.
카드 결제를 선택한다.
결제 버튼을 클릭한다.
예상 결과: 결제가 완료되고 주문 완료 화면으로 이동
실제 결과: 결제 버튼 클릭 후 화면이 멈추며 더 이상 진행되지 않음
