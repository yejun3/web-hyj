결함 조치 문제
문제 1. 결함 조치 우선순위 결정

쇼핑몰 시스템 테스트 중 다음 결함이 발견되었다.

결함   내용
A   결제 버튼을 눌러도 결제가 진행되지 않음
B   상품 상세 화면의 글자색이 설계서와 다름
C   다른 사용자의 개인정보가 조회됨
D   상품 검색 결과가 평소보다 2초 늦게 표시됨

개발 인력이 부족하여 한 번에 하나의 결함만 수정할 수 있다.

문제

위 결함의 조치 우선순위를 1순위부터 4순위까지 작성하고, 1순위와 2순위로 선정한 이유를 서술하시오.
순위 : C -> A -> D -> B 순서
1순위 : 개인정보 노출이 보안과 사용자 피해에 영향을 끼치는 심각한 오류 사항
2순위 : 사용자가 실제 결제를 수행할 수 없어 쇼핑몰의 핵심 업무가 중단되기 때문
3순위 : 서비스 이용이 가능하지만 성능에 영향을 준다.
4순위 : 기능 수행에는 직접적인 영향을 주지 않으므로 상대적으로 우선순위가 낮다.

문제 5. Stub과 Mock의 차이

회원가입 기능은 다음과 같이 동작한다.

회원가입
→ userRepository.save()
→ emailService.sendWelcomeEmail()

다음 두 가지 테스트 요구사항이 있다.

① findById(1)을 호출했을 때 VIP 회원을 반환하도록 한다.
② 회원가입 후 sendWelcomeEmail()이 정확히 한 번 호출되었는지 확인한다.

문제

①과 ②에 각각 적합한 Test Double을 작성하고 그 이유를 설명하시오.
5-1 Stub을 사용하는 것이 좋다.
- 특정 메서드를 호출했을 때 미리 준비된 결과를 반환하여 테스트에 필요한 상태를 만들기 때문이다.
5-2.Mock를 사용하는 것이 적합하다.
- Mock은 반환값뿐만 아니라 객체 간의 호출 행위를 검증하는데 사용되기 때문이다.

동등 클래스 기법으로 대표값 3개

문제 7. 모델 기반 상태 전이 테스트

쇼핑몰 주문 상태는 다음과 같다.

주문 접수
→ 결제 완료
→ 배송 준비
→ 배송 중
→ 배송 완료

시스템 요구사항은 다음과 같다.

결제가 완료되지 않은 주문은 배송을 시작할 수 없다.
배송 완료된 주문을 다시 배송 준비 상태로 변경할 수 없다.
문제

위 요구사항을 상태 전이 테스트 관점에서 다음과 같이 작성하시오.

정상적인 상태 전이 2개
- 주문 접수 -> 결제 완료
- 배송준비 -> 배송중
허용되어서는 안 되는 상태 전이 2개
- 결제완료 없이 배송준비로 넘어가는 상태
- 배송완료 -> 배송준비
- 주문접수 -> 배송중
상태 전이 테스트를 사용하는 이유
- 정상적인 상태이동뿐만 아니라 허용되지 않는 잘못된 상태 이동까지 검증할 수 있기 때문에 업무 흐름에서 발생할 수 있는 오류를 찾는데효과적이다.

   ↓

장애 복구 테스트를 위해 사용자가 서비스를 이용하고 있는 상태에서 WAS1 프로세스를 강제로 종료하였다.

문제 10. Error, Fault, Failure, Defect 판단

회원가입 요구사항은 다음과 같다.

만 20세 이상인 사용자만 가입할 수 있다.

개발자가 요구사항을 구현하면서 실수로 다음 코드를 작성하였다.

if (age > 20) {
    register();
}

그 결과 20세 사용자가 회원가입을 시도했지만 가입이 거부되었다.

문제

위 상황을 다음 네 가지 개념과 연결하여 각각 설명하시오.

Error : 개발자가 >=작성해야하는데 >를 작성한 사람의 실수
Fault : 잘못 작성된 조건 age>20 자체를 의미한다.
Failure : 프로그램을 실행했을 때 사용자가 실제로 회원가입에 실패한 현상
Defect : 위의 Error, Fault, Failure를 포함하여 관리되는 문제 전체를 의미한다.

문제 13. 결함 판단 기준 적용

상황 A
