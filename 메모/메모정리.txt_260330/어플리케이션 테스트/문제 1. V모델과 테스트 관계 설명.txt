문제 1. V모델과 테스트 관계 설명

소프트웨어 개발 프로젝트에서 V모델(V-Model)을 적용하여 테스트를 수행하려고 한다.

다음 요구사항에 따라 답하시오.

조건

V모델이 무엇인지 작성하시오.
- V 모델은 소프트웨어 개발 단계와 테스트 단계를 서로 대응시켜 개발 테스트를 함께 계획하는 개발모델이다.

개발 단계와 테스트 단계가 서로 대응되는 이유를 작성하시오.
- 각 개발 단계에서 만든 산출물이 올바르게 구현되었는지 대응되는 테스트를 통해 검증하기 때문이다.

다음 개발 단계에 대응하는 테스트를 모두 작성하시오.
요구분석 -> 인수테스트
아키텍처 설계 -> 시스템 테스트
모듈 설계 -> 통합 테스트
구현 -> 단위테스트
-------------------------------
문제 2. 프로젝트 수행 단계별 테스트 설명

다음은 쇼핑몰 프로그램을 개발하는 프로젝트이다.

학생은 프로젝트에서 수행하는 단위 테스트, 통합 테스트, 시스템 테스트, 인수 테스트를 이해해야 한다.

조건

각 테스트에 대해 다음 내용을 모두 작성하시오.

- 단위 테스트 
목적 : 하나의 기능이나 모듈이 정상적으로 동작하는지 확인한다.
대상 : 메서드, 클래스, 서비스 등 작은 단위
수행자 : 개발자

- 통합테스트
목적 : 모듈 간 연결과 인터페이스가 정상적으로 동작하는지 확인한다.
대상 : 컨트롤러 ,서비스, DAO 등의 연결
수행자 : 개발자 또는 테스트 담당자

- 시스템 테스트
목적 : 전체 시스템이 요구사항에 맞게 동작하는지 확인한다.
대상 : 전체 시스템
수행자 : 테스트 팀

- 인수 테스트
목적: 실제 사용자의 업무를 수행하기에 적절한지를 확인한다.
대상 : 실제 업무 절차
수행자 : 사용자 또는 고객

문제 3. 구조 기반 테스트와 명세 기반 테스트 비교

학생은 테스트 케이스를 설계하는 방법을 학습하였다.

다음 요구사항에 따라 답하시오.

조건

구조 기반 테스트와 명세 기반 테스트를 비교하여 다음 항목을 모두 작성하시오.

구조기반 테스트
기준 : 프로그램 내부 구조
코드확인 : 확인함
종류 : 화이트박스 테스트

코드확인 : 확인하지 않음
종류 : 블랙박스 테스트
목적 : 입력과 출력 및 요구사항 검증

문제 4. 상향식 통합 테스트와 하향식 통합 테스트 설명

Spring Boot 프로그램에서 Controller, Service, DAO를 이용하여 통합 테스트를 수행하려고 한다.

다음 요구사항에 따라 답하시오.

조건

상향식 통합 테스트를 설명하시오.
- 하위 모듈부터 상위모듈 방향으로 결합하여 테스트 하는 방법

하향식 통합 테스트를 설명하시오.
- 상위 모듈부터 하위모듈 방향으로 결합하여 테스트 하는 방법

Driver와 Stub의 역할을 각각 작성하시오.
Driver - 아직 개발되지 않은 상위모듈을 대신하여 하위모듈을 호출하는 임시 프로그램 -> 가짜 상위 모듈
Stub - 아직 개발되지 않은 하위모듈을 대신하여 미리 준비된 결과를 반환하는 임시 프로그램 -> 가짜 하위 모듈

문제 5. 인수 테스트 종류 설명

개발이 완료된 병원 예약 시스템을 실제 운영하기 전에 인수 테스트를 수행하려고 한다.

다음 요구사항에 따라 답하시오.

조건

다음 인수 테스트에 대해 수행자와 확인 내용을 각각 작성하시오.

- 사용자 인수 테스트 
수행자 : 업무 담당자 , 고객
- 확인내용 :  업무절차와 요구사항 충족 여부

- 운영상의 인수테스트
수행자 : 시스템 운영자 , 관리자
확인내용 : 백업, 복원, 장애복구, 계정과닐

- 계약 인수 테스트
수행자 : 품질 담당자 , 감사 담장자
확인내용 : 법규, 보안, 산업 표준 준수 여부

- 규정 인수 테스트
수행자 : 개발 조지 내부 고객
확인 내용 : 규정 준수 여부 확인

- 알파테스트
수행자 : 개발 조직 내부 인원
확인 내용 : 내부 환경에서 제품 확인

- 베타 테스트
수행자 : 실 사용자
확인 내용 : 실제 환경에서 제품 사용
