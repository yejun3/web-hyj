문제 1. 테스트 단계 판단

온라인 쇼핑몰의 주문 기능을 개발하고 있다.

개발자는 다음 메서드가 상품 가격과 주문 수량을 이용하여 정확한 주문 금액을 계산하는지 확인하려고 한다.

public int calculateTotalPrice(int price, int count) {
    return price * count;
}

테스트할 때 데이터베이스, Controller, 다른 Service와의 연결은 사용하지 않고 해당 메서드만 독립적으로 검증하려고 한다.

문제

위 상황에서 수행해야 할 테스트 종류를 작성하고, 그렇게 판단한 이유를 2가지 이상 서술하시오.
- 수행해야할 테스트 : 단위 테스트 
- 이유 :  calculateTotalPrice()라는 하나의 작은 기능 단위를 독립적으로 테스트하기 때문이다.
            데이터 베이스나 다른 모듈과의 연결을 제외하고 해당 매서드 자체가 올바르게 동작하는지 확인하기 떄문이다.
            프로그램 전체가 아닌 계산 로직 하나를 대상으로 검증하기 떄문이다.

회원가입 시스템의 요구사항이 다음과 같다.

회원의 나이는 14세 이상 100세 이하인 경우에만 가입할 수 있다.

학생은 이 요구사항에서 경계 부분에 오류가 발생할 가능성이 있다고 판단하여 경곗값 분석을 적용하려고 한다.

    if (price >= 50000) {
        discount = 5000;

    return price - discount;

입력 : 60000
결과 : 55000

결정 커버리지는 100%인가? x
- 조건식의 결과 중 거짓 결과를 실행하지 않았기 떄문이다.

결정 커버리지 100%가 아니라면 추가할 테스트 데이터를 하나 작성하시오.

: 수량에 99999999와 같은 값을 입력한다.
 허용하지 않은 입력에 대해 오류 처리 및 입력 제한이 정상적으로 수행되는지 확인한다.

문제 10. 요구사항 기반 테스트 케이스 종합 설계

온라인 교육 시스템에 다음 요구사항이 있다.

수강신청 요구사항
학생은 원하는 강좌를 신청할 수 있다.
하나의 강좌에는 최대 30명까지 신청할 수 있다.
이미 30명이 신청한 강좌에는 추가 신청할 수 없다.
동일한 학생은 동일한 강좌를 두 번 신청할 수 없다.
신청이 성공하면 수강신청 목록에 해당 강좌가 표시되어야 한다.

현재 상황은 다음과 같다.

강좌명 : Java Programming
현재 신청 인원 : 29명

학생 1001 : 해당 강좌 신청 이력 없음
학생 1002 : 해당 강좌 이미 신청함
문제

위 요구사항을 검증하기 위해 다음 3개의 테스트 케이스를 작성하시오.

정상 수강신청  
현재 29명, 학생 1001은 미신청 -> 학생 1001이 수강신청 -> 예상 결과 신청 인원 30명 , 수강신청 목록에 강좌 표시

최대 인원 초과
-> 최대인원 테스트에는 이미 30명이 신청한 상태에서 추가 학생이 신청하면 시스템이 신청을 거부해야한다.

중복 수강신청
-> 중복 신청 테스트에서는 이미 같은 강좌를 신청한 학생이 다시 신청할 경우 두번 쨰 신청이 등록되지 않아야 한다.

각 테스트 케이스에는 반드시 다음 항목을 작성하시오.

사전조건
수행 내용
예상 결과
