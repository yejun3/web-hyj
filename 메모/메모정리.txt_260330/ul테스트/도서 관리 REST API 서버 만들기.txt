도서 관리 REST API 서버 만들기

도서관에서 보유하고 있는 도서 정보를 관리하기 위한 REST API 서버를 개발한다.
화면은 구현하지 않으며, Spring Boot 서버 프로그램만 작성한다.

Client
   ↓
Controller
   ↓
Service
   ↓
Repository
   ↓
Database


데이터베이스는 MySQL을 사용한다.
test_db 사용

BookEntity 작성 조건

book

다음 필드를 작성한다.

필드명   자료형   설명   조건
id   Long   도서 번호   PK, 자동 증가 id는 GenerationType.IDENTITY 전략
title   String   도서 제목   NULL 불가
author   String   저자   NULL 불가
price   int   도서 가격   
category   String   도서 분야   
stock   int   재고 수량
---------------------------------------------------
BookDTO 작성 조건

클라이언트와 도서 데이터를 주고받기 위한 BookDTO 클래스를 작성한다.

다음 필드를 가진다.

private Long id;
private String title;
private String author;
private int price;
private String category;
private int stock;

Lombok을 이용하여 Getter, Setter, 생성자, Builder를 사용할 수 있도록 작성한다.

또한 BookEntity를 전달받아 BookDTO 객체로 변환할 수 있는 생성자를 작성한다.

다음과 같이 사용할 수 있어야 한다.

BookDTO dto = new BookDTO(entity);

private String error;

BookRepository 작성 조건

BookRepository는 JpaRepository를 상속받아 작성한다.

Entity 타입은 BookEntity, 기본키 타입은 Long을 사용한다.

제목 검색
도서 제목에 특정 문자열이 포함된 도서를 검색한다.


카테고리 검색
특정 카테고리와 일치하는 도서를 조회한다.

BookService 작성 조건

BookService는 BookRepository를 주입받아 사용한다.

다음 기능을 작성한다.

1. 도서 등록
2. 전체 도서 조회
3. 도서 ID 조회
4. 제목으로 도서 검색
5. 카테고리별 도서 검색
6. 도서 정보 수정
7. 도서 삭제

Service는 Entity를 데이터베이스에 저장하고 조회하는 역할을 Repository에 위임한다.

Controller에는 BookEntity를 직접 반환하지 않고 BookDTO로 변환하여 반환한다.

BookController 작성 조건

기본 요청 주소는 다음과 같다.

/books

Controller는 BookService를 주입받아 사용한다.

모든 Controller 메서드의 반환형은 다음과 같이 작성한다.

ResponseEntity<?>

모든 결과는 ResponseDTO에 저장한 후 다음 형식으로 반환한다.

return ResponseEntity.ok().body(response);

------------------------------------------------------------------------------------

작성 순서 
[1단계] DTO & ResponseDTO (데이터 그릇 제작)
  ▼
[2단계] BookEntity (DB 테이블 설계도 제작)
  ▼
[3단계] BookRepository (DB와 대화하는 창고지기 제작)
  ▼
[4단계] BookService (비즈니스 로직 및 가공 처리)
  ▼
[5단계] BookController (사용자 요청 관문 및 응답)

데이터 흐름
1. 요청(사용자)가 주소창에 요청을 보냄 Controller가 이 요청을 받아줌 그리고 Service로 넘김
2. Service는 Repository에게 실행할 명령을 내림 -> Repository 가 DB에서 데이터를 꺼내와서 Service에게 돌려줌
3. Service 내부에서 DB 꺼내온 데이터를 사용가능한 형태인 DTO로 바꾸어줌
4. 포장시킨 DTO를 Control에게  넘겨주고 이를 최종 규격인 ResponseDTO에 담음
5. ResponseEntity를 통해 성공실패여부 등과 함께  인터넷망으로 사용자에게 전해줌

1단계
데이터를 담을 틀 , 포장지 제작 DTO클래스
4가지 어노테이션이 기본적으로 써짐 
@Builder // 매개변수 순서 상관없이 쓸수있도록 유연성을 높이는 build형태로 객체조립
@NoArgsConstructor //매개변수 없는 기본생성자 자동 생성
@AllArgsConstructor // 매개변수 있는 기본생성자 자동 생성
@Data // 롬복: getter, setter를 쓸 필요 없이 자동완성

2단계 
DB와 연결될 설계도 Entity 제작
자바의 객체이지만 데이터베이스와 직접 연결
데이터 흐름: Service ⇄ Repository ⇄ Database
