제어 역전 (Inversion of Control)
우리가 직접 객체를 만드는 것이 아니라, 스프링이 객체를 만들고 필요한 곳에 주입해주는 것

1. 스프링 객체로 만들도록 클래스에 @Component 어노테이션을 붙인다.

@Component
Public class Engine{
              Public void start(){"부릉"} <-매서드
}

@Component
Public class Car{
        Engine engine;

      engine.start();
}

스프링 부트는 new를 통해 객체를 새로 만들 필요없이 @Component가 붙은 애들을 객체 컨테이너에 저장을 해두고 필요한 위치에 꺼내서 직접 넣어주는 역할을 ㅎ나다. 


2. 프로젝트를 실행하면 필드로 사용되는 곳에 만들어놨던 객체를 주입하여 메서드를 사용할 수 있도록 해준다.

의존성 주입
1. 필드에 직접 주입
2. setter의 매갭변수 자리에 주입
3. 생성자의 매개변수 자리에 주입

gradle
다양한 프로그래밍 언어를 지원하는 빌드 자동화 도구
의존성 관리, 테스트 실행, 배포, 패키징 등의 빌드 작업을 자동화하며 유연성과 확장성을 중시한다.

필요한 라이브러리가 있으면 build.gradle파일의 dependencies 부분에 링크를 붙여넣으면 스프링이 자동으로 다운받는다.

mvnrepository에서 링크를 복사해온다.

스프링 프로젝트는 대개 레이어드 아키텍처 패턴으로 이루어져 있다.
표현 계층 : 클래스 이름뒤에 Controller를 많이 붙인다.
- htttp 요청 처리
- 응답처리
- 비즈니스계층의 메서드를 호출
비즈니스 계층 : 클래스 이름 뒤에 Service를 많이 붙인다.
- 실제 업무를 수행
영속 계층 : 클래스 이름 뒤에 Repository를 많이 붙인다.
- 데이터베이스와 직접 통신하는 계층
자신과 맞닿아 있는 계층만 이동이 가능하다.

컨트롤러
클라이언트 HTTP 요청을 받아서 적절한 기능을 실행하고 처리결과를 HTTP 응답으로 반환하는 계층이다.

1. 사용자가 브라우저, 모바일 앱, Post 같은 프로그램을 통해 서버에 요청을 한다. (URL을 적어서 요청)

요청방식 : GET
요청 주소 : /users/1
전달 데이터 : 1

http://localhost:10000/users/10

@RestController : 해당 클래스가 컨트롤러로 취급되기 위한 어노테이션
ㄴ @Controller + @ResponseBody을 합친 어노테이션

@ResponseBody : 응답결과를 데이터로 주는 어노테이션

@Component(부모)
|
@Controller(자식)
|        ㄴ @RestController(자손)
@Service
|
@Repository

@RequsetMapping("/users") : 클래스에 붙인다.
@GetMapping("/users") : 메서드에 붙인다.
클라이언트의 HTTP 요청을 Controller 메서드와 연결하는 역할을 한다.

클래스 주소 + 메서드 주소 합쳐지게 된다.

@PathVariable 
주소의 일부분을 변수로 하여 데이터를 가져오는 어노테이션

http://localhost:10000/users/10

@GetMapping("users/{id}") <- id에 10이 들어감
public String findUser(@passVariable Long id){
   //  id를 메서드 내부에 씀
}

@RequestParam 검색 조건이나 옵션에서 사용하는것이 REST API 설계의 관례  
URL의 쿼리스트링에 포함된 값을 받아오는 어노테이션
http://localhost:10000/users?name=홍길동
