문제 1. 빌드와 배포의 구분
정답
적절하지 않다.
빌드(Build)란 소스코드를 컴파일·패키징하여 실행 가능한 산출물을 생성하는 과정이다.
배포(Deployment)란 생성된 실행 파일이나 필요한 자원을 대상 환경에 전달하고 설치·적용하여 실제로 사용할 수 있도록 하는 과정이다.
빌드는 실행 가능한 산출물을 만드는 과정, 배포는 만들어진 산출물을 대상 환경에 적용하는 과정이다.
JAR 파일이 생성되었다고 해서 운영 서버에 정상적으로 적용되고 실행되는 것은 아니기 때문이다.
해석 풀이

쉽게 구분하면:

Source Code → Build → JAR 생성 → Deploy → 운영 서버 적용

입니다.

예를 들어 order.jar가 정상적으로 만들어졌더라도

운영 서버에 전송되지 않았거나
잘못된 서버에 배포되었거나
잘못된 경로에 복사되었거나
재기동되지 않았거나
환경설정이 잘못되었다면

운영 배포가 완료된 것이 아닙니다.

핵심 암기

빌드 = 만든다 / 배포 = 적용한다

문제 2. 애플리케이션 배포 단위
정답
항상 적절하지 않다.
애플리케이션 배포 단위란 운영환경에 함께 적용되어야 하는 프로그램 및 관련 자원들의 묶음이다.
실행 파일, 설정 파일, DB Script, 배포 Script, 라이브러리 등을 포함할 수 있다.
실행 파일만으로 프로그램이 정상 실행되지 않을 수 있기 때문이다.
다음을 확인한다.
배포 파일
버전
설정 파일
DB 변경 Script
라이브러리
배포 Script
대상 서버
배포 경로
해석 풀이

예를 들어:

order.jar
application.properties
update.sql
deploy.sh

가 하나의 변경사항이라면 order.jar만 복사하면 안 됩니다.

application.properties가 변경되었는데 누락하면 설정 오류가 발생할 수 있고, update.sql이 필요한데 실행하지 않으면 DB 구조와 프로그램이 맞지 않을 수 있습니다.

핵심 암기

배포 = 실행파일 하나가 아니라 운영에 필요한 자원 전체

문제 3. 코드 인스펙션
정답

하드코딩
예외처리 문제

문제 19. 배포 장애와 Rollback
정답

가장 먼저 고려할 수 있는 방법은 Rollback입니다.

Rollback

현재 장애를 발생시킨 신규 버전을 제거하거나 이전 정상 버전으로 되돌리는 것입니다.

v1.9 정상
↓
v2.0 배포
↓
결제 장애
↓
Rollback
↓
v1.9 복구
Rollback 전 확인
이전 버전 존재 여부
이전 설정 파일
DB 변경 여부
데이터 호환성
서비스 영향
승인 여부
핵심 암기

문제 20. 운영·유지보수 조직으로의 이관
정답

개발팀의 방법은 적절하지 않다.

전달해야 할 산출물 예:

실행 파일
소스코드
설계서
DB 설계서
운영자 매뉴얼
설치/배포 절차서
장애 대응 절차서
테스트 결과서
환경설정 정보
형상관리 정보
왜 필요한가?

운영팀은 프로그램을 단순히 실행하는 것만 하는 것이 아닙니다.

운영 중 문제가 발생하면:

장애 발생
↓
원인 파악
↓
로그 확인
↓
서비스 재기동
↓
설정 확인
↓
필요시 개발팀 협업

을 해야 합니다.

따라서 설계서, 매뉴얼, 장애 대응 절차 등이 필요합니다.

핵심 암기

운영 이관 = 프로그램 파일만 넘기는 것이 아니라 운영에 필요한 모든 산출물을 인계

⭐ 시험 직전 핵심 암기 20개

특히 아래는 문제에서 표현만 바꿔서 자주 물어볼 수 있습니다.

개념	시험용 한 줄 답
빌드	소스코드를 실행 가능한 산출물로 만드는 과정
배포	산출물을 대상 환경에 전달·설치·적용하는 과정
Check Out	저장소에서 작업공간으로 가져오는 것
Check In	변경사항을 저장소에 반영하는 것
CI	지속적으로 통합하고 자동 빌드·테스트하는 것
코드 인스펙션	실행하지 않고 코드를 검토하는 활동
정적 분석	프로그램 실행 없이 분석
동적 분석	프로그램 실행 후 분석
오탐	실제 문제가 아닌데 문제로 탐지
테스트 커버리지	테스트가 코드 등을 얼마나 수행했는지 나타내는 지표
Web Server	HTTP 처리 및 정적 콘텐츠 제공
WAS	애플리케이션 및 동적 콘텐츠 처리
프로젝트 Rule	프로젝트 특성에 맞춘 추가 검사 규칙
통합 빌드	소스 통합 후 빌드·검증 결과 확인
운영 접근	서버·네트워크·계정·권한·보안정책 확인
운영 이행	개발 산출물을 운영환경에 적용
Rollback	이전 정상 버전으로 복구
배포 장애	전송뿐 아니라 실행·설정·기능까지 확인
운영 이관	개발팀 → 운영/유지보수 조직에 산출물과 지식 전달
이관 검증	실제 전달 자료와 승인된 이관 목록/산출물을 비교
⭐ 가장 헷갈리기 쉬운 5개

① 빌드 vs 배포

빌드 = 만들기
배포 = 적용하기

② Check Out vs Check In

Out = 저장소에서 가져오기
In = 저장소에 넣기

③ 정적 vs 동적

정적 = 실행 안 함
동적 = 실행하면서 검사

④ 오탐

실제 문제 X → 도구가 문제라고 판단

⑤ Rollback

신규 버전 장애 → 이전 정상 버전으로 되돌리기
