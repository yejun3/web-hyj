MSA 및 클라우드 환경에서 서비스 간 연계 데이터 보안을 강화하기 위해 적용할 수 있는 대표적인 전송 구간 보안 기술 및 인증 방식을 2가지 이상 제시하고 그 필요성을 서술하시오.

- OAuth2 및 JWT : 서비스 간 API 통신 시 사용자/서비스의 자격 증명을 매번 DB에서 확인하지 않고 전달받은 JWT의 서명을 검증하여 빠르게 접근 원한을 확인한다. API 토큰 탈취 및 무단  API위조 호출을 차단하기 위해 필수적으로 적용된다.

암호화 알고리즘
SEED
- 1999년 한국인터넷진흥원(KISA)과 국내 암호학자들이 자체 개발한 128비트 대칭키 블록 암호 알고리즘
- 개발 배경 : 미국 중심의 암호 기술 수입 의존도를 낮추고 국내 전자상거래 및 인터넷금융의 보안을 강화하기 위해 국산 표준으로 개발되었다.
- 주요 특징 
블록 크기 : 128비트(16바이트)
키 기링 : 128비트.256비트
구조 : 파이스텔 구조 기반 
규격 : 대한민국 국가 표준
ARIA
- 2004년 국가정보원과 산학연 전문가들이 개발한 국가 표준 대칭키 블록 암호화 알고리즘
- 개발배경 : 기존 SEED 알고리즘이 경량 환경이나 경량 경량화 기기, SW 경량화 환경에서 효율이 떨어지는 단점을 보완하고 AES 알고리즘과의 경량/경쟁 호환성을 위해 개발되었다.
- 주요 특징
블록크기 : 128비트
키 길이 : 128, 192, 256비트 지원
구조 : SPN 구조 
장점 : 경량화 환경에 유리하며 하드웨어 및 소프트웨어 구현 시 비트 연산 위주로 동작하여 속도가 빠르고 경량 기기에 적합하다.
AES
- 2001년 미국 표준기술연구소가 공모를 통해 지정한 세계적 표준 대칭키 블록 암호 알고리즘이다.
- 개발배경 : DES의 키 길이가 짧아 해킹 위험이 높아짐에 따라 전 세계 표준으로 활용할 강력한 암호화 표준의 필요성으로 탄생했다.
- 주요 특징
블록 크기 : 128비트
키 길이 : 128비트, 192비트, 2256비트
구조 : SPN
장점
- 안정성, 속도, 메모리 효율성이 뛰어나며 현재 전 세계 대부분의 연계보안에서 가장 널리 쓰이는 사실상의 글로벌 표준이다.

암호화 KEY를 관리하는 방식
1. KEY VALUT(키 볼트) 
소프트웨어 기반의 클라우드 암호화 키/비밀번호 관리 서비스
보관대상 : DB 암호화 키 뿐만 아니라 API 인증키, 비밀번호, SSL/TLS 증명서 등 다양한 비밀정보를 한 곳에서 관리한다.
접근제어 : 어플리케이션이 Key Vault에 접근할 떄 정당한 권한이 있는지 확이한 후 키를 제공하거나 Vault 내부에서 직접 암복호화를 수행해준다.
2.HSM(Hardware Security Module)
암호화 키의 생성, 보관, 처리 연산만을 전담하도록 특별히 제작된 ‘특수 물리 하드웨어 장비
물리적 보안성 : 장비 내부의 키는 절대 외부로 추출할 수 없도록 설계되어 있다
침입 탐지 밎 자멸 기능 : 누군가 장비를 강제로 열거나 물리적인 공격을 시도하면 내부에 저장된 키를 즉시 하드웨어 수준에서 파기한다.
연산 전담 : 암복호화 연산을 암호화 전용 하드웨어칩이 직접 수행하므로 서버의 CPU 부하를 줄여준다.

대칭키 : 하나의 암호키로 암호화 복호화를 수행
장점
- 매우 빠르다.
- 대용량 데이터의 적합
단점
- 키를 안전하게 전달해야한다.

비대칭키 암호화 : 공개키를 통해 암호화하고 개인키를 통해 복호화한다.

공개키(Public Key)
- 누구나 볼 수 있도록 공개된 키 
- 데이터를 암호화 하거나 , 전자 서명을 검증할 때 사용
- 인터넷이나 연계 시스템을 통해 누구에게나 자유롭게 배포할 수 있다.
- 공개키로 암호화된 데이터는 오직 그와 짝을 이루는 개인키로만 복호화 할 수 있다.
- 공개키가 외부에 노출되어도 해당 키로는 데이터를 복호화 할 수 없기 때문에 안전하다.

개인키(Private Key)
- 소유자 본인만 안정하게 보관해야 하는 비밀 키 
- 암호화된 데이터를 복호화 하거나 전자서명을 생성할 떄 사용한다.
- 절대로 외부에 유출되어서는 안되며 HSM이나 Key Vault 같은 보안 저장소에 안전하게 보관해야 한다.
- 개인키를 분실하거나 유출당하면 암호화된 데이터가 해독되거나 타인이 나를 사칭할 수 있게 된다.

시나리오

B기업은 신규 통합 시스템을 구축하면서 연계 모듈 구현 환경을 설계하고 있다.

프로젝트 책임자는 다음과 같은 목표를 제시하였다.

데이터 오류를 최소화한다.
개인정보를 안전하게 보호한다.
시스템을 지속적으로 확장할 수 있도록 한다.
REST API를 이용하여 다른 시스템과 쉽게 연동한다.
문제

위 목표를 달성하기 위해 연계 모듈 구현 환경 조성 시 반드시 고려해야 하는 사항을 4가지 작성하고, 각각의 이유를 간단히 서술하시오.
- 데이터 품질 및 일관성 확보 
- 데이터의 중복, 지연, 손실을 방지하기 위해 데이터 검증과 오류 로깅이 필요하다.
보안성 확보
-SSL/TLS, OAuth2, JWTm AES 등을 이용하여 데이터와 시스템을 안전하게 보호해야 한다.
유연한 확장성 고려 
- 클라우드 및 MSA 환경에서 시스템을 쉽게 확장할 수 있도록 설계해야한다.
표준화 및 상호 운용성 확보
- RESTful API와 JSON/XML 등 표준 기술을 적용하여 다양한 시스템과 원할하게 연계해야 한다.
