화면 설계
UI 요구사항 확인
UI에 대한 정의 -> 화면으로 보는 모근 것 (색상, 폰트, 버튼, 요소들의 배치)
UI 구성요소
1. 시각적 디자인 : 색상, 글꼴, 아이콘, 이미지, 레잉아웃
2. 상호작용 디자인 : 시스템의 반응
3. 정보구조 : 사용자가 원하는 정보를 쉽게 찾을 수 있도록 만드는 설계
ㄴ 메뉴 : 기능을 어떻게 나눌지 -> 홈, 검색, 장바구니, 마이페이지
ㄴ 콘텐츠 분류 : 정보를 어떤 기준으로 묶을지 -> 최신순, 인기순, 카테고리별
ㄴ 화면 흐름 : 사용자가 어떤 순서로 화면을 이동할지 -> 목록 -> 상세 -> 결제
UX에 대한 정의 -> 사용자가 서비스를 사용하면서 느끼는 전체적인 경험
UX 구성요소
1. 사용성 : 별도의 설명 없이 얼마나 쉽게 이용할 수 있냐
ㄴ 버튼이 큼, 메뉴 위치가 직관적임
2. 유용성 : 사용자가 요구한 기능이 있는가?
ㄴ 서비스에 사용자가 요구한 기능이 있는가?
3. 매력도 : 서비스가 사용자에게 얼마나 매력적인지 정도
ㄴ 아이콘, 폰트 등이 마음에 들어야 사용을 한다.
4. 접근성 : 연령, 장애여부, 환경에 상관없이 사용할 수 있는가?
ㄴ 장애인 , 고령자고 서비스를 이용할 수 있는가
5. 신뢰성 : 서비스에 대한 사용자의 믿는 정도
ㄴ 광고가 많다, 오류가 자주 발생한다. -> 신뢰도가 많다.

UI/UX의 관계
- 다른 개념이지만 실제 서비스에서는 떼놓을 수 없는 관계
UI가 UX를 만드는 중요한 수단이다.
- 사용자는 서비스 내부 구조를 직접 보는게 아니라 대부분 화면, 버튼, 메뉴, 입력창, 색상, 문구를 통해 서비스를 경험하기 떄문이다.

좋은 UI가 항상 좋은 UX를 보장하지는 않는다.
- 화면이 예쁘고 세련되어도 사용하기 불편하면 좋은 UX가 아니다.

좋은 UX를 위해서는 UI뿐만이 아니라 전체 흐름도 중요하다.

UI/UX 표준
- 화면을 설계할 떄 지켜야하는 공통 기준
- 사용자가 웹사이트나 앱을 일관성 있게, 편리하게, 안전하게, 접근 가능하게 사용할 수 있도록 정해둔 설계 원칙

ISO 9241-210
ISO : 국제 표준화 기구(산업 전반에 걸친 표준을 제정하는 곳)
적용대상 : 사용자의 컴퓨터가 상호작용하는 대상 전부
주요내용 : 사용자 중심 설계 6대 원칙
1. 사용자는 설계 과정 전반에 적극적으로 참여해야 한다.
- 실제 사용자가 요구사항 수집, 분석 등 전 과정에 참여하여 사용자 의견이 설계에 반영되어야 한다.
2. 사용자 중심 설계는 전체 사용자 경험을 고려해야 한다.
- 단순 기능 만족이 아니라 정서/인지적 경험을 포함해야 한다.
3. 설계는 반복적으로 이루어져야 한다.
- 의견을 피드백하고 보완하는 과정을 반복해야 한다.
4. 설계는 사용자와 소프트웨어 구축 목표 및 환경을 기반으로 한다.
- 사용자의 업무 환경을 고려해야한다.
ㄴ 병원 : 데스크톱, 배달 앱 : 스마트폰
5. 사용자 중심 설계 팀은 여러 학문 분야가 함께 협력해야한다.
- 좋은 UX는 한 사람이 만들 수없다.
- 기획자, UI디자이너, UX 디자이너, 개발자, 관리자가 협업해야 한다.
6. 사용자 평가에 반드시 포함되어야 한다.
- 개발자끼리 테스트하는 것이 아니라 실제 사용자가 테스트 해야된다.

UI 요구사항 확인하기
1. 소프트웨어 개발을 위한 사용자 화면 표준 및 지침 확인하기
- 국내 지침

- 국제 UI/UX 표준

- 플랫폼별 디자인 가이드라인 수집하고 분석

- 기존 유사 응용 소프트웨어 UI 설계 사례를 조사하고 분석

2. 목표 응용소프트웨어의 UI 요구사항 확인하기
- 목표 응용소프트웨어의 기능 및 사용자를 분석
//ㄴ 사용자의 어떤 문제를 해결하고자 하는지, 목표가 뭔지, 알기 위해 문서, 제안서, 회의록을 검토
//- 목표 응용소프트웨어의 기능목록을 작성하고 이를 유형으로 분류한다.
//ㄴ 어떤 기능을 가지고 있고 비슷한거 끼리 묶어라
//- 사용자를 식별하여 정의한다.
//ㄴ 사용자 유형, 연령대, 주요 업무 특성, IT 활용능력을 정의
//- 사용자기기, 운영체제, 이용 시간대를 분석
//- 사용자 경험상의 주요 고려사항 도출
//- 기능별 사용자 시나리오 작성하기

- 업무의 특성을 고려하여 UI 구성 요소 및 흐름을 파악한다.

- 사용자 면담 및  UI/UX 요구사항 수집하기

- UI 요구사항 도출 및 정리

- UI 요구사항 검토 및 확정

[Q9] '접근성(Accessibility)'의 개념을 정의하고, 본문에서 지적한 '색상만으로 성공/실패를 구분하는 잘못된 사례'가 색약 사용자에게 미치는 문제점과 이를 해결하기 위한 '개선 사례'의 핵심 원리를 서술하시오.
답: 
접근성이라는 것은 장애인, 고령자, 신체적 제약이 있는 사람을 포함한 모든 사용자가 어떤 환경에서든 차별없이 시스템을 이용할 수 있도록 보장한는 정도를 의미한다. 

색약사용자에게 미치는 문제점 : 화면에 경고나 성고 메세지를 띄울 떄 단순하게 빨간 테두리, 초록색 테두리로만 구분하게 두면 적녹색약 사용자는 
상태를 구분할 수 없다.

개선 : 색상이라는 하나의 시각 단서에만 의존하지 않고 텍스트 메세지나 명확한 아이콘을 함께 결합하여 색을 보지 않고도 정보를 명확하게 인지할 수 있도록 설계

[Q10] 스마트폰이나 태블릿 같은 모바일 플랫폼과 PC 환경인 데스크톱 플랫폼은 조작 방식과 화면 특성이 다릅니다. 가이드라인에 명시된 두 플랫폼의 핵심 차이점과 그에 따른 UI 설계 시 고려사항을 비교하여 서술하시오.
답:
모발일 플랫펌 : 화면 크기가 제한적이다. 손가락 터치 및 제스처로 조작한다. 버튼 크기를 크게 설계해야 하고 정보 밀도를 낮춰 한번에 하나의 작업에 집중할 수 있도록 단일 열 배치 선호

데스크톱 플랫폼 : 화면에 놃고 모니터를 사용하며, 마우스와 키보드를 통해 정밀하고 세밀하게 조작이 가능하다. 따라서 한 화면에 많은 양의 정보를 
효율적으로 배치할 수 있으며, 마우스 전용 상호작용을 적극 활용할 수 있다.

[Q11] UI(User Interface)와 UX(User Experience)는 밀접하지만 서로 다른 개념입니다. 본문에 제시된 자동차 비유를 활용하여 두 개념의 차이점을 상세히 설명하시오.
답:

UI : 자동차의외형 디자인, 핸들, 계기판, 가속 페달, 브레이크 내비게이션 화면 등 운전자가 직접 눈으로 보고 손으로 조작하는 '물리적, 시각적 요소' 그 자체를 의미한다.

UX : UI를 활용하여 운전자가 주행하면서 느끼는 승차감, 조작의 편리함, 직관성, 만족감, 피로도 등 '총체적인 경험과 지각'을 의미한다.

디자인이 아무리 화려하더라도 불편하면 경험이 좋지 않을 수 있다.

[Q12] 국제 표준 ISO 9241-210에서 강조하는 핵심 원칙 중 하나는 "설계는 반복적으로 이루어져야 한다"입니다. 본문에서 예시로 든 '회원가입 버튼' 사례를 포함하여, 이 반복적 설계 과정이 어떤 순서 순환 구조로 진행되는지 기술하시오.
답: 

요구사항 파악 -> 설계 디자인 -> 프로토타입 제작 -> 시용자 테스트/ 평가 -> 문제 발견 및 개선의 순환 구조를 가진다.

[Q13] 인터랙션 설계 품질을 높이기 위한 '좋은 상호작용(Interaction)'의 세 가지 분석 항목(직관성, 효율성, 피드백 제공)에 대해 각각의 개념이나 예시를 들어 설명하시오
답:

직관성: 사용자가 별도의 메뉴얼이나 가이드 없이도 UI의 형태만 보고 기능을 곧바로 조작하고 이해할 수 있는 성질
 (돋보기 아이콘 -> 검색, 집 아이콘 -> 홈 화면)

효율성 : 사용자가 우너하는 목표나 테스크를 달성하기 까지 거치는 단계를 최소화하여 시간과 노력을 줄여주는 성질

피드백 제공 : 사용자가 시스템에 특정 행동을 했을 떄, 시스템이 그 결과를 즉각적이고 명확하게 인지시켜 주는 것
(저장 버튼 눌렀을 떄 "성공적으로 저장되었습니다." 메세지 띄우기)

[Q14] 사용자 조사 및 면담 과정에서 질문자가 범하기 쉬운 오류를 방지하기 위해 '중립성'을 유지해야 합니다. 본문에 제시된 잘못된 질문 예시와 올바른 질문 예시를 비교하여 중립성 유지가 왜 중요한지 설명하시오.
답:

잘못된 질문의 예시 : "현재 우리 앱 메뉴의 구조가 너무 복잡해서 사용하기 불편하지는 않나요?"
-> 질문자 본인의 주관적 판단을 섞어 부정적 답변을 유도함

올바른 질문 예시 : "현재 우리 앱 메뉴 구조를 이용할 떄 어떤 느낌을 받으셨나요"
- > 선입견 없이 사용자의 순수한 의견을 이끌어냄

중립성 유지가 중요한 이유 : 질문자가 유도성 질문을 던지면 사용자는 솔직한 의견 대신 질문자의 의도에 맞춘 왜곡된 답변을 하게 된다. 
잘못된 요구사항 수집으로 이어져 결국 사용자 중심 설계에 실패하는 원인이 되기 떄문에 객관적인 중립성 유지가 매우 중요하다.



와이어 프레임
- 화면의 구조와 배치를 설계한 설계도
- 디자인보다 구조에 집중한 구조
버튼 위치, 메뉴위치, 정보 배치, 화면 이동흐름을 확인하는 것이 목적이다.
- 빠르게 작성한다. (초기 아이디어를 검증하기 위한 도구이므로 세세하게 그리지 않는다.)
